What is AEM CoderExperience Modernization Console — aemcoder.adobe.io — Last updated October 9, 2026

aemcoder.adobe.io is Adobe's Experience Modernization Console — a hosted, browser-based, AI-assisted development environment for Edge Delivery Services (EDS). It connects directly to your GitHub repository and enables developers and non-developers to interact with their EDS site using natural-language prompts, with zero local environment required.

It is part of the Brand Experience Agent family in AEM as a Cloud Service and accelerates website migrations, block development, design extraction, and ongoing site maintenance through AI automation combined with full developer governance.

Core Capability Summary

💬
Interactive AI Chat
Natural-language prompts drive all operations. Plan or Execute mode.
👁️
Live AEM Preview
See changes rendered instantly. Desktop, tablet, mobile viewports.
🔀
Code Diff Viewer
Review every AI-generated file change as a diff before staging or pushing.
🐙
GitHub Integration
Stage, branch, sync, push, and create PRs — all inside the console.
🎨
Figma Integration
Extract design tokens and migrate blocks directly from Figma files.
📋
Project Documentation
Auto-generate Author, Developer, Admin PDF guides for project handover.

Challenges & How to Resolve Them24 known challenges across 5 categories

2.1  Access & Setup Challenges

C1Access is gated — console not freely available
Root Cause

Early-access program with managed onboarding. Requires Adobe account manager approval before any use.

Resolution

Contact your Adobe account manager to request access. Work at aemcoder.adobe.io cannot begin until approved. Access is tied to your Adobe ID.

C2Console cannot inspect code — GitHub app missing
Root Cause

AEM Code Connector GitHub app not installed on the repository. Without it the console has no code access.

Resolution

Install the AEM Code Connector GitHub app on bhasakatech/eds-events-gehealthcare. Navigate to: GitHub repo → Settings → Integrations → GitHub Apps.

C3Code sync not working after push
Root Cause

AEM Code Sync GitHub app not installed. This app is what syncs pushed code to the EDS CDN.

Resolution

This project (boilerplate-based) likely already has AEM Code Sync installed. Verify at GitHub → Settings → Integrations. If missing, install from github.com/apps/hlx-code-sync.

C4Cannot create PRs — token has no write access
Root Cause

GitHub personal access token in Adobe Cloud Manager was created read-only. The console needs write access to push branches and open PRs.

Resolution

Cloud Manager → Repositories → Manage Access Tokens → edit the token → add write access to repository code. Cloud Manager re-validates the repository automatically.

C5fstab.yaml mismatch — console connection fails
Root Cause

Site name or host in fstab.yaml is wrong, or file is not committed to main before connecting the console.

Resolution

This project: fstab.yaml already points to author-p139816-e1765605.adobeaemcloud.com with org bhasakatech. Verify values and ensure committed to main.

2.2  Content Migration Challenges

C6Protected / intranet content not scraped
Root Cause

Content behind authentication, VPN, or a firewall is not accessible to the agent's headless Chromium scraper.

Resolution

Use SLICC (browser-context scraping) to access protected content. Or allow-list agent IPs in your firewall: 34.228.136.112 · 54.90.51.39 · 3.224.194.242

C7Complex dynamic content not captured
Root Cause

JavaScript-heavy SPAs or content requiring user interaction (click, scroll, hover) to appear in the DOM.

Resolution

Client-side rendered content accessible via a direct URL is supported. CSS-hidden content (tabs, accordions, carousels) is captured as it exists in the DOM. Server-driven dynamic data requires separate custom block development.

C8Bulk import fails — no infrastructure found
Root Cause

Single-page migration was skipped. Bulk import requires parsers, transformers, and page templates created during initial single-page migration.

Resolution

Always migrate at least one representative page per template before running bulk import. This is mandatory — bulk import reuses the infrastructure, it does not infer templates from scratch.

C9Block CSS does not match source design
Root Cause

Design tokens (Phase 1) not extracted before individual block styling (Phase 2). Block CSS references brand.css variables that don't exist yet.

Resolution

Complete Phase 1 of design migration first: "Migrate the design from https://events.gehealthcare.com". This generates styles/brand.css with all tokens before any block CSS is written.

C10Navigation links render as buttons
Root Cause

Document Authoring automatically wraps links in button classes, affecting navigation link items visually.

Resolution

header.js must strip button classes from nav links. The agent's Navigation Setup skill handles this automatically. Prompt: "Set up navigation from https://events.gehealthcare.com"

C11Dynamic Media / Scene7 image URLs broken after import
Root Cause

Images re-imported as static renditions instead of preserving DM URLs, losing responsive and on-the-fly image transformations.

Resolution

The agent automatically detects DM/Scene7 sources and preserves them as DM URLs during migration. No manual intervention required — handled transparently for both DA and UE migrations.

2.3  AI Context & Prompt Challenges

C12Agent loses context mid-conversation
Root Cause

AI context window is finite. Long sessions compact or forget earlier instructions, especially project-specific rules and naming conventions.

Resolution

(a) Add INSTRUCTIONS.md or CONTEXT.md to repo root with brand guidelines and block rules. (b) Start every new session: "Warm up by reading the project documentation". (c) If lost, clear chat and restart with warm-up.

C13Agent makes wrong block mappings
Root Cause

Ambiguous source HTML structure or missing project context. Agent defaults to generic patterns when project-specific guidance is absent.

Resolution

Use iterative prompting — let the agent ask clarifying questions and answer them one at a time. Do not front-load all requirements in the first prompt. Refine mappings interactively after each migration step.

C14Block critique never reaches 85% similarity
Root Cause

Source and migrated content differ structurally. Critique runs a maximum of 3 auto-fix iterations and stops regardless of score reached.

Resolution

After 3 iterations, manually review the diff viewer in Code view. Apply targeted CSS or structural fixes via specific follow-up prompts using Inspect mode to select the exact element needing correction.

C15AI generates inaccurate or misleading responses
Root Cause

General LLM limitation — the model can hallucinate, misinterpret source HTML, or suggest non-optimal patterns.

Resolution

Always review AI-generated code in the diff viewer before staging. Never push without human review. The GitHub PR review step is the final governance gate before any change reaches production.

2.4  AEM Authoring / Universal Editor Challenges

C16Wrong boilerplate used for AEM Authoring project
Root Cause

Standard EDS boilerplate used instead of the xwalk-specific boilerplate required for Universal Editor projects.

Resolution

Use aem-block-collection-xwalk as the template. This project already uses aem-boilerplate-xwalk — correct. No action needed.

C17paths.json causes errors in AEM authoring flow
Root Cause

paths.json at the repo root conflicts with the AEM authoring setup when connecting the console to a Universal Editor project.

Resolution

Delete paths.json from the repo root and commit the deletion to main before connecting the console. This is a required step for AEM Authoring projects.

C18Content upload package fails
Root Cause

Admin permissions or Agent Permissions not enabled in the console settings. The agent cannot access the AEM admin API without explicit authorization.

Resolution

Settings → Agent Permissions → enable: "Allow LLM to access admin.hlx.page on my behalf". Also verify you have admin access to the AEM project in Cloud Manager.

C19Content not visible in AEM after upload
Root Cause

Preview was not triggered after content was uploaded to AEM. Content exists in the repository but has not been published to the AEM preview environment.

Resolution

Go to Document Authoring (da.live/#/bhasakatech/eds-events-gehealthcare), open the uploaded page, click the paper plane icon (top-right), then select Preview.

2.5  Code Quality & Deployment Challenges

C20Linting fails after agent writes code
Root Cause

AI-generated JavaScript or CSS may not fully comply with the project's ESLint (Airbnb rules) or Stylelint (standard) configuration.

Resolution

Run npm run lint:fix after any agent-generated changes before staging. The Push modal triggers GitHub PR checks that include linting — failures block the merge.

C21Changes not appearing in preview after push
Root Cause

AEM Code Sync has a 3–5 second processing delay after a push before changes are live on the preview CDN.

Resolution

Wait 3–5 seconds after the push completes, then hard-refresh the preview tab with Ctrl+Shift+R. The console's Refresh icon also re-fetches the preview rendering.

C22Images showing "about:error" in preview
Root Cause

createOptimizedPicture not called in block JS, or called before the final DOM structure has been assembled by the decorator.

Resolution

Call createOptimizedPicture only after the final DOM restructuring is complete. Prompt the debugging skill: "Debug why images show about:error in the event-hero block".

C23PageSpeed Insights score drops after migration
Root Cause

Unoptimized assets committed to git, or heavy JS/CSS loaded eagerly. Author-uploaded images are auto-optimized by EDS; git-committed images are not.

Resolution

Optimize all assets before committing to git. Use lazy-styles.css for non-critical CSS and delayed.js for MarTech. Run PSI against the feature preview URL — target score: 100.

C24Workspace reset loses all uncommitted work
Root Cause

"Reset workspace" in the Settings → Danger Zone was triggered. This action is permanent and irreversible — the workspace returns to its initial state.

Resolution

Always stage and push all changes to GitHub before touching the Danger Zone. Treat it like dropping a database — never click it with any unstaged work in the workspace.

How Many Ways to Use This Tool6 distinct usage modes — fully automated to fully manual
aemcoder.adobe.io — Prompt Input Controls
Mode 01
💡
Plan Mode — Analyze Only
Toggle the lightbulb icon. The agent analyzes your request and describes its intended approach step-by-step — no files are changed. Use this before committing to understand exactly what will happen.
Best for: scoping migrations · reviewing block strategy · assessing impact before execution
"Plan how to migrate https://events.gehealthcare.com/events/rsna-2026" → Agent outlines: 5 sections identified, 3 new blocks needed, files to be created: event-hero.js, brand.css, nav.md No files written. Plan only.
Mode 02
🪄
Execute Mode — AI-Driven Development
Toggle the magic wand icon. The agent carries out the full plan and writes actual file changes. All changes appear in the Code → Changes view as diffs before you stage or push anything.
Best for: running migrations · block creation · design extraction · bulk imports
"Migrate the design from https://events.gehealthcare.com" → Creates: styles/brand.css (+142 lines) → Updates: styles/styles.css, all block CSS files Diffs visible in Code → Changes before staging.
Mode 03
⏱️
Prompt Queue — Automated Sequential Execution
Click the clock icon to queue multiple prompts. Each executes only after the previous one completes. Set your workflow and step away — results accumulate in the diff viewer.
Best for: unattended long migrations · overnight batch workflows · multi-step pipelines
Queue (runs in order, each awaits the last): 1. "Migrate the page https://events.gehealthcare.com/events/rsna-2026" 2. "Migrate the design from https://events.gehealthcare.com" 3. "Critique site" 4. "Create documentation for this project"
Mode 04
🔍
Inspect Mode — Targeted Element Context
Click the select icon (⊹) in the workspace toolbar. Click any element on the live page preview — the agent receives that element's exact HTML as context in the chat panel. Surgically target specific fixes.
Best for: fixing specific layout issues · targeting broken elements · precise style corrections
Click the event-hero title element on the preview page, then: "Fix the font size and weight of this element to match the source" → Agent receives the exact <h1> HTML as context No guessing — it sees exactly what you clicked.
Mode 05
📄
File Context Mode — Code-Level Targeting
In Code → Files view, select any file or highlight specific lines, then click Add to chat. The file content is attached to the chat as context. Ask the agent to modify, explain, or refactor specific code.
Best for: modifying a specific block JS or CSS file · explaining existing code · targeted refactors
Select lines 44–78 of event-hero.js → Add to chat, then: "Refactor this section to handle missing mediaCell gracefully and fall back to a solid purple background when no image is provided"
Mode 06
🎮
Demo Mode — Risk-Free Exploration
Available automatically on first sign-in before connecting a real project. A pre-configured Adobe demo site is provided. Explore every feature — migrations, critiques, design extraction — without touching your repo.
Best for: team onboarding · evaluating capabilities · training · proof-of-concept before committing
Activated automatically at first login. Banner at bottom of screen: "You are in Demo Mode" Exit → Settings → Connect Your Site → Authorize AEM Code Connector with GitHub credentials → Your repo is now the active workspace
